# Android USB serial

The NDK library preserves the GSerial GObject API. Its JNI backend delegates USB
protocols to the MIT-licensed [usb-serial-for-android](https://github.com/mik3y/usb-serial-for-android)
drivers, pinned to v3.10.0, commit `a8b9ecc7d32ce6df749c44a2b9e8cb208ac30609`.
The vendored sources are unchanged; `source.json` records their SHA-256 hashes.
The separate `BuildConfig.java` supplies the constant normally generated by the
upstream Gradle library module. Driver coverage is that release's probe table;
not every USB device with a UART is supported.

SQGI's Android packager copies the installed `usr/share/sqgi-android/java` sources
into the APK. Include `androidx.annotation:annotation` when building another app;
SQGI already supplies it. Android builds install the JNI initialization header,
GIR, typelib, Java sources, license, and provenance alongside `libgserial-1.0.so`.
Production builds leave `android_test_backend=false`.

## Building and testing

Use the pinned SQGI Android toolchain (NDK 28.2.13676358, API 31 or newer):

```sh
sqgipkg setup --platform android --check --emulator --native-tools
sqgipkg build --manifest examples/android/sqgipkg.json --platform android --arch arm64-v8a
sqgipkg build --manifest examples/android/sqgipkg.json --platform android --arch x86_64
```

The separate regression manifest enables a Java loopback fixture:

```sh
sqgipkg build --manifest examples/android/sqgipkg.test.json --platform android --arch x86_64
sqgipkg install --manifest examples/android/sqgipkg.test.json --platform android --arch x86_64 --serial emulator-5564
sqgipkg run --manifest examples/android/sqgipkg.test.json --platform android --arch x86_64 --serial emulator-5564
sqgipkg logs --manifest examples/android/sqgipkg.test.json --platform android --arch x86_64 --serial emulator-5564 --logs-once
```

Look for `GSERIAL_USB_TEST_PASS`. This checks packaged JNI/GI discovery,
permission rejection, cancellation, denial/grant, binary partial I/O, explicit
modem outputs, close/reopen from a data callback, and detach cleanup. The fixture
does not emulate an FTDI chip or the Android permission dialog. The SQGI emulator
does not expose USB host hardware; actual adapter transfers require a phone or
tablet with USB host support.

To export production `extras-gserial` packages for both ABIs using Ooblerg's
inventory/ELF/GI validator:

```sh
tools/package-android.sh ../ooblerg /absolute/path/to/staged-repository gserial-usb-r1
```

This builds the production example and writes immutable module catalogs under
`android/modules/noble-android-r4/gserial-usb-r1/<triplet>/v1/`. The exporter rejects
incomplete inventories and missing dependencies. It does not publish a server
or replace an existing release. `examples/android/sqgipkg.ooblerg.json` consumes
`extras-gserial` instead of compiling the library. For a local repository, pass
`--android-repository http://127.0.0.1:PORT` and `--android-sdk` pointing to the
matching base SDK. SQTheia already selects `extras-gserial`; its catalog must
contain this updated package before it can use the discovery API.

## Embedding without SQGI

Package the installed Java sources in the application's class loader. From an
application JNI entry point, call `gserial_android_initialize(env, context, &error)`
once before other GSerial operations. It retains the application context and
class loader for the process lifetime. SQGI apps discover those services
automatically, including in Android worker processes. No Activity pointer is
retained and no Java callback holds a native GObject pointer.

The application needs USB host support. It can declare
`<uses-feature android:name="android.hardware.usb.host" android:required="false"/>`
when it should also install on devices without USB. USB access is granted by the
system's per-device permission prompt, not a manifest runtime permission. Device
intent filters are optional; enumeration works without them.

## I/O and RFD900 integration

Configure the port while closed. For an RFD900 connected through an FTDI USB
adapter, select that adapter and use the radio's configured UART baud with 8N1
and no hardware flow control. The example uses 57600; SQTheia preserves the
user's saved baud. Enumeration identifies the USB adapter, not the attached
radio model, and never sends radio configuration commands.

Android reads use a background reader with a bounded 64 KiB buffer. Overflow,
detach, or transfer failure closes the port through the usual `disconnected`
signal on the GLib main loop. Writes return the actual accepted byte count;
retry the remainder. USB writes use at least a 1 ms timeout because the Android
drivers treat zero as infinite. A successful write does not acknowledge delivery
to the robot. Keep writes in SQTheia's serial worker. DTR and RTS are only changed
when explicitly requested through `set_control_lines()`; some MCUs need them,
while toggling them can reset boards.

Hardware acceptance remains necessary: verify permission allow/deny, the
radio's baud, bidirectional binary traffic, unplug/replug, two identical adapters,
screen/background transitions, and sustained telemetry on an actual OTG device.
Use stable serial-number identities where available and keep the application's
existing link-loss handling active.
